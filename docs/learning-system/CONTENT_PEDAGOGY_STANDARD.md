# 学习内容生成与教学标准

版本：1.0

确立日期：2026-08-07

适用范围：LLM Wiki 学习模块生成、展示、审校和验收任何领域的知识点。

## 1. 文档目的

LLM Wiki 不能只把资料切成标题、摘要和关系节点。一个知识点必须让零基础学习者能够理解、复述、举例、判断边界并迁移到新场景，才算形成可学习内容。

例如系统从物理教材提取出“加速度”后，不能只显示“速度变化率”；它还要解释速度是什么，用汽车起步和转弯展示两种变化，说明常见误解，并让学习者判断“高速匀速行驶是否有加速度”。

本标准与 `LEARNING_FRAMEWORK.md` 配合使用：八步流程规定学习者怎样学，本文件规定每一步需要什么质量的内容。两者发生冲突时，不能为了缩短页面而删掉理解所需的信息。

## 2. 完成的定义

### 2.1 内容深度必须按用途分级

系统不应强迫所有节点使用完全相同的篇幅和视觉数量。面向主课程、考试目标或关键决策的“核心节点”使用完整教学链；只负责补前置、回答追问或提供背景的“补充节点”可以合并板块，但仍要让初学者读懂。

例如一门AI课程可以把“基础模型”做成含反差、完整例子、系统图和证据的核心节点；把“状态估计”做成含准确概念、机器人被推后的一个例子、流程和边界的补充节点。补充节点可以更短，但不能只留下“融合多传感器数据”这种需要再次查词的定义。

分级时必须记录节点为什么属于核心或补充、它服务哪条学习路线，以及什么条件会触发升级。一个补充节点如果被选入课堂PPT、现场演示或关键考核，必须先升级到核心标准。

一个节点只有同时达到以下结果，才可以标记为“内容完整”：

1. 学习者知道它在整个知识体系中的位置。
2. 页面不依赖未解释的专业词才能读懂。
3. 至少一个例子完整展示输入、过程和结果。
4. 至少两个表面不同的例子揭示同一个规律。
5. 页面说明什么时候适用、什么时候可能失败。
6. 重要事实能追溯到资料中的具体证据。
7. 学习者能够不看答案复述，并解决一个新场景问题。

例如“缓存”节点不能只写“缓存提高性能”；完整内容要展示第一次加载、暂存结果、再次读取、旧结果未更新的失败场景，并让学习者解释“头像已经更换但页面仍显示旧头像”的原因。

## 3. 四项教学依据

### 3.1 先展示完整过程，再让初学者独立完成

系统应优先提供逐步完成的示例，再逐渐减少提示。初学者直接面对陌生问题时，注意力容易耗在猜步骤，而不是理解步骤之间的关系。

例如学习平均数时，先展示“2、4、6 相加等于 12，再除以 3 得到 4”，之后再让学习者计算新的数据。

依据：Sweller 与 Cooper 关于完整例题的研究发现，初学者研究逐步示例，通常比直接求解陌生问题用时更少、错误更少。来源：<https://www.jstor.org/stable/3233555>。

### 3.2 比较不同例子，帮助提炼共同结构

系统不能只给一个故事。至少两个例子要明确映射共同步骤，避免学习者只记住表面场景。

例如“汽车刹车”和“球改变方向”都可以解释加速度，但系统必须指出：前者改变速度大小，后者改变速度方向，两者共同点是速度发生了变化。

依据：Gentner、Loewenstein 与 Thompson 的研究显示，引导学习者比较两个案例，更有利于提炼共同结构并迁移到新问题。来源：<https://groups.psych.northwestern.edu/gentner/papers/GentnerLoewensteinThompson03.pdf>。

### 3.3 图文同步，复杂动画分段

视觉内容必须解释当前步骤，不能只是装饰。一个复杂动画应支持暂停、分步和当前重点提示。

例如解释水循环时，先突出蒸发，再突出凝结，最后突出降水；不能让所有箭头同时运动而没有文字对应。

依据：Moreno 关于分段和提示的研究表明，把复杂动态过程拆成小段，有助于降低初学者的理解负担。来源：<https://onlinelibrary.wiley.com/doi/10.1002/acp.1348>。

### 3.4 用主动复述检查掌握，不用“看过”代替“学会”

系统应要求学习者不看原文解释、判断和迁移。重新阅读可以保留，但不能成为唯一的掌握证据。

例如学完供需关系后，让学习者解释“演唱会票数量不变但想买的人突然增加，价格为什么可能上涨”，而不是只选择“我已阅读”。

依据：Roediger 与 Karpicke 的研究表明，主动回忆既能检查学习，也能改善较长时间后的记忆。来源：<https://pubmed.ncbi.nlm.nih.gov/16507066/>。

## 4. 每个知识节点的 18 个内容板块

页面可以按需折叠，简单知识点可以缩短篇幅，但不能把必要板块变成一句含糊摘要。

### 01. 体系位置

说明主要父节点、严格前置、推荐前置、同层概念、下游用途和跨主题联系，并用自然语言解释关系。

例如“瞬时速度”主要属于“物理 → 力学 → 运动”，严格前置是平均速度，并与数学中的导数建立跨主题关系。

### 02. 学习目标

写成可检查的动作，不能只写“了解”或“掌握”。

例如“能够根据一段运动描述，判断速度大小或方向是否发生变化”，比“掌握加速度”更容易检查。

### 03. 前置知识回顾

每个前置概念提供一句大白话回顾、一个例子和跳转入口。学习者可以选择继续当前节点或先补前置知识。

例如学习百分比增长前，先回顾“百分比表示每一百份中占多少份”。

### 04. 要解决的问题

先说明现实困难和旧方法的不足，再出现专业名称。

例如数据库索引出现前，系统可能需要逐行翻找全部记录；数据变多后，这种查找越来越慢。

### 05. 以前与现在

比较同一类任务在采用该知识或方法前后的变化，至少说明流程、结果和限制。

例如没有索引时像逐页找名字，有索引后像先查目录；但目录本身也需要维护空间。

### 06. 一句话本质

只使用已解释词汇，一口气可以读完，并能统领后续内容。

例如“索引就是额外保存一份方便查找的位置目录”。

### 07. 直观模型或生活类比

明确写出哪里相似、哪里不同，避免把类比当成真实机制。

例如电流可以暂时类比水流，但电子运动与水管中的水并不完全相同。

### 08. 完整示范例子

逐步给出输入、执行者、动作、中间结果和最终结果。涉及数字时应展示实际计算；涉及操作时应展示每一步可观察结果。

例如解释二分查找时，展示在 1—100 中猜数字：先猜 50，根据“大了”缩小到 1—49，再继续缩小。

### 09. 第二个迁移例子

更换表面场景并标出与第一个例子的对应关系。

例如把“在有序数字中查找”迁移到“在按字母排序的通讯录中找名字”。

### 10. 真实应用

说明该知识在真实工作、科学、生活或软件中的职责，并区分它与其他组成部分的分工。

例如机器学习模型可以预测需求，但采购制度、库存空间和工作人员仍共同决定最终补货。

### 11. 失败例子与常见误解

至少包含一个失败场景、一个相似但不属于本概念的反例，以及错误理解的纠正。

例如相关性高不自动证明因果关系；冰淇淋销量和溺水事件都在夏季增加，不代表冰淇淋导致溺水。

### 12. 专业词解释

正文中的陌生词必须连接到概念词典。解释框同时支持鼠标悬浮、点击、键盘聚焦和触摸操作。

每个词条至少包含：一句大白话、为什么需要、具体例子、当前职责、不负责什么、前后概念和深入解释。

例如“参数”先解释为“系统内部会被训练改变的数字”，再用垃圾邮件线索影响力说明，而不是继续用“权重优化”这种未解释术语。

### 13. 原理阶梯

按“日常语言 → 具体数字或动作 → 符号含义 → 公式或规则 → 代入同一例子 → 适用条件 → 限制”展开。没有数学的领域可以把公式替换为正式规则或流程条件。

例如报销制度可先展示一次完整报销，再引入“金额超过 5,000 元需要部门负责人和财务负责人共同批准”的正式条件。

### 14. 完整流程

每一步必须写清输入、执行者、动作和输出。流程长度由真实因果决定，不强行限制在固定步数。

例如文件导入知识库不是“上传后完成”，而是读取文件、提取内容、分段、建立索引、生成知识页、检查结果。

### 15. 系统与关系框架

说明继承、组合、验证和顺序关系。一个结果由多部分共同产生时，不能全部归因给最显眼的模块。

例如医疗诊断系统可以组合模型、设备、医生和检查流程；临床结果负责现实验证，不是模型内部的一个步骤。

### 16. 证据摘要

在链接前说明来源、方法、关键结果、支持的结论、不能推出的结论、可信程度和资料位置。

例如产品官方演示可以证明画面中功能成功运行，但不能自动证明所有用户、所有环境都稳定成功。

### 17. 掌握检查

至少包含复述、判断、排序或演算、新场景迁移和参考答案。不同知识类型按需要选择，但不能只考术语记忆。

例如学习缓存后，让学习者解释“为什么强制刷新后头像才更新”，并提出一个不应缓存的场景。

### 18. 教学或演示提取卡

这是可选显示、必须保存的教学扩展。包含快速讲法、标准讲法、展开讲法、开场问题、可能回答、揭晓、追问、转场和可跳过位置。

例如公司培训可以用 30 秒讲清请假流程，也可以展开例外条件和审批演练；底层知识内容保持同一份。

## 5. 术语解释的递归完整性

不能用多个陌生词解释一个陌生词。词条正文中出现的新术语，也必须拥有词条或就地解释。

系统应提供两层解释：

- 快速解释：一句大白话和一个例子，避免打断主线。
- 深入解释：准确机制、数字过程、相关概念、适用条件和限制。

例如“梯度”快速解释为“提示每个可调数字往哪个方向改，能让错误下降”；深入层再说明斜率、多个方向和局部变化。

内容生成后应执行术语检查：发现一个词只有链接但没有可读解释时，节点不能标记为完整。

## 6. 例子组合标准

每个节点默认需要四类例子：

1. 生活类比，建立第一直觉。
2. 完整数字或动作示范，走通真实过程。
3. 现实应用，说明知识的实际位置。
4. 失败反例，说明边界和误解。

复杂概念应增加多个迁移例子。例子不是越多越好；每个例子必须承担明确作用，并在页面上说明它与核心原理的对应关系。

例如“反馈”可以用调水温建立直觉，用恒温器展示完整动作，用机器人抓取展示现实应用，用传感器延迟导致震荡展示失败。

## 7. 视觉内容标准

### 7.1 最低配置

复杂知识节点至少包含：知识位置图、输入到输出流程图、完整例子图。简单规则节点可以合并图形，但必须保留清楚的流程或条件结构。

例如“公司访客登记”不需要三张炫目图片，但必须有“到达—登记—核验—授权—离开”的清楚流程图。

### 7.2 形式选择

- 抽象机制使用简洁矢量图。
- 数字变化使用图表或逐步演算图。
- 真实影响使用来源清楚的照片、视频或关键帧。
- 循环与反馈使用可暂停、可分步的动画。
- 动画保存静态关键帧，保证打印和减少动画模式仍能理解。

### 7.3 一图一任务

一张图只解释一个主要变化，文字与箭头必须对应当前步骤。

例如“图片数字化”只展示现实图片、像素和数字，不在同一画面继续塞入神经网络训练和模型部署。

### 7.4 无障碍

视觉内容需要文字说明，不能只依靠颜色；动画尊重减少动画设置；放大到 200% 仍能阅读主要标签。

例如正确与错误不能只使用绿色和红色，还要同时显示“正确”“错误”或不同图形标记。

## 8. 证据与来源标准

系统生成解释时，应把事实、来源陈述、推断和未知情况分开：

- 直接事实：资料明确支持。
- 来源方说法：企业、作者或机构自行陈述，尚无独立确认。
- 推断：系统根据多项证据作出的合理连接，必须标明是推断。
- 冲突：可靠资料给出不同结论。
- 未确认：缺少决定性证据。

每个证据摘要至少保存标题、作者或机构、日期、资料位置、研究或说明对象、方法、关键结果、支持的结论和限制。

例如软件官网写“速度提升 10 倍”时，页面应标记为厂商披露，并说明测试条件；没有独立测试时不能改写成普遍事实。

## 9. 与八步学习流程的对应

| 学习步骤 | 主要调用的节点内容 | 学习者实际看到的结果 |
| --- | --- | --- |
| 定 | 体系位置、学习目标 | 知道正在学什么、学会后能做什么 |
| 图 | 前置关系、系统框架 | 看清父子、前后和跨主题关系 |
| 懂 | 一句话本质、类比、原理阶梯 | 从直觉走到准确解释 |
| 联 | 迁移例子、真实应用 | 把新知识接到已有经验和现实场景 |
| 练 | 完整示范、逐步练习 | 先模仿完整过程，再减少提示 |
| 测 | 复述、判断、演算 | 不看答案检查是否真正掌握 |
| 迁 | 新场景问题、反例 | 判断规律在不同场景是否仍成立 |
| 复 | 精华、错题、证据卡 | 根据薄弱处复习，不必重读全部内容 |

例如用户在“懂”阶段打开参数解释，在“练”阶段跟着邮件分类示范，在“迁”阶段把相同结构应用到图片识别。

## 10. 长内容的界面规则

内容完整不等于一次全部展开。界面需要支持：

- 固定目录和当前阅读位置。
- 前置知识就地回顾或跳转。
- 板块折叠和全部展开。
- 术语悬浮、点击、键盘和触摸解释。
- 图片放大、动画暂停与逐步播放。
- 上一个和下一个知识点。
- 打印当前展开内容或完整内容。
- 无横向滚动。

例如用户阅读到一个长节点的证据区时，仍能看到自己位于第 16 个板块，并一键返回完整示范。

制作规则、内部验收语言和内容生成提示不得显示在学习正文。例如“这一段用于吸引注意”属于内部规则，用户页面只显示实际内容。

### 10.1 知识结构与真实脉络必须分开表达

同一批知识至少允许两种阅读方式：

- **知识结构**回答“完整系统由什么组成、哪些知识互相依赖”。例如人形机器人由视觉感知、状态估计、任务规划、反馈控制、电机和机械结构共同组成。
- **真实脉络**回答“旧方法遇到什么问题、后来出现了什么改变、旧技术怎样与新技术汇合、最后在哪里接受现实检验”。例如不能写成“大模型发明了机器人控制”，应写成“长期存在的机器人控制与 2020 年代的多模态基础模型汇合，使机器人更容易理解开放指令”。

真实脉络中的每个节点至少保存：大致时期、关系类型、以前的困难、承接的能力、新突破、仍需的系统、打开的下游能力、真实例子、证据摘要和一句教师转场话。时间无法精确到年份时，应写“长期基础”“2010 年代后逐步发展”等可信范围，不能为了画一条漂亮时间线虚构年份。

关系类型必须至少区分四类：

1. **历史里程碑**：在某个时期明显改变了主流做法。例如 2017 年 Transformer 论文提出以注意力为核心的架构。
2. **长期支撑**：早于当前热点出现，而且至今仍是完整系统的一部分。例如反馈控制长期负责根据传感器偏差实时修正电机命令。
3. **技术汇合**：不同技术在系统中组合，不表示其中一方发明了另一方。例如视觉—语言—动作模型要与机器人数据、规划、控制和硬件汇合。
4. **现实验证**：论文实验、临床试验、公开产品或真实部署检验技术是否工作。例如 Rentosertib 进入临床研究是现实验证，不是基础模型自然生长出的“下一层网络”。

界面优先使用一条纵向故事线，课堂主节点直接展开，备课节点按阶段折叠。节点详情页要显示“从哪里接过来 → 解决什么旧问题 → 带来什么新能力 ＋ 仍然离不开什么”，并能返回原来的脉络位置。例如点开 Figure × 宝马后，应能返回机器人汇合阶段，而不是只回到整棵知识树顶部。

每个脉络阶段至少有一张真正解释关系的图，或复用一段已经核对来源的真实视频。图负责说明因果与分工，视频负责展示现实中发生了什么；两者不能互相冒充。例如 Figure 工厂视频可以证明画面中的任务发生了，但“传感—规划—控制—硬件”概念图不能冒充 Figure 企业内部架构。

## 11. 数据与生成流程要求

后续实现内容生成时，应把长内容保存为结构化板块，而不是只保存一段富文本。结构至少能够表达：前置关系、目标、例子类型、步骤、术语引用、视觉资源、证据摘要、限制、练习和答案。

例如系统需要知道某段是“失败反例”，才能在迁移练习和课堂提取时复用；如果全部混在一段 Markdown 中，就难以检查缺项或生成不同学习路线。

推荐生成顺序：

1. 从来源中识别知识边界和证据。
2. 建立父子、前置、并列和跨主题关系。
3. 写学习目标、问题和一句话本质。
4. 识别所有可能陌生的术语。
5. 生成完整示范、迁移例子、真实应用和失败反例。
6. 生成原理阶梯、流程与系统框架。
7. 选择或生成真正解释内容的视觉资源。
8. 生成逐来源证据摘要。
9. 生成复述、判断、演算和迁移任务。
10. 执行完整性、证据和术语检查。
11. 未通过检查的节点标记为“待补”，不得显示为完整。

## 12. 内容状态

节点内容状态至少区分：

- 骨架：只有标题和关系，适合导航，不代表已经能够学习。
- 待补：部分解释存在，但缺少必要例子、证据、视觉或练习。
- 可学习：核心教学链完整，学习者可以完成理解和练习。
- 已审校：内容、来源、术语、例子和界面经过人工或可靠规则检查。

例如只有“反向传播：误差向后传递”一句话的节点属于骨架；加入完整数字示范但没有来源和掌握检查时仍属于待补。

## 13. 自动完整性检查

未来的生成或审校工具至少检查：

- 是否存在未解释术语。
- 学习目标是否可以实际检查。
- 是否有完整示范和第二个迁移例子。
- 是否有现实应用与失败反例。
- 流程每一步是否包含输入、动作和输出。
- 重要事实是否有证据摘要，而不只是链接。
- 来源方说法和独立事实是否区分。
- 是否有复述和新场景迁移任务。
- 视觉资源是否与解释对应且可以访问。
- 前置和下游链接是否形成可走通的路线。
- 结构关系与历史脉络是否分开，是否把长期基础错误写成新技术的后代。
- 每个脉络节点是否有时期、旧问题、新突破、仍需条件、真实例子和来源摘要。
- 课堂主节点与折叠备课节点合计是否与知识库节点数一致，且没有重复。

例如节点有三张图片，但图片都只是装饰照片，没有解释任何步骤，视觉检查仍应判定为未完成。

## 14. 人工验收清单

每个准备交付的节点必须逐项回答“是”：

- [ ] 不看项目代码也能理解一句话本质。
- [ ] 前置知识可以就地回顾或跳转学习。
- [ ] 所有专业词都有大白话解释和具体例子。
- [ ] 至少一个示范完整走通输入、过程和结果。
- [ ] 至少两个例子明确比较共同结构。
- [ ] 原理从直觉逐步走到准确规则或公式。
- [ ] 现实应用说明了各组成部分的分工。
- [ ] 失败反例和常见误解齐全。
- [ ] 重要事实有证据摘要和限制。
- [ ] 学习者可以完成复述、判断或迁移练习。
- [ ] 图片、动画和文字互相对应。
- [ ] 键盘、鼠标、触摸和减少动画模式可用。
- [ ] 页面没有内部制作提示或无意义装饰。
- [ ] 节点状态与实际完整度相符。

## 15. 规则优化与版本管理

本文件是学习模块的长期产品规则。新增规则应先说明解决了什么学习问题，再在代表性节点上验证，最后同步到生成模板、数据结构、界面和检查工具。

例如如果“损失函数”试点发现词条必须增加“它不负责什么”，后续应把该字段加入通用概念词典和完整性检查，而不是只在一个页面手工补一句。

规则更新不能静默降低既有节点标准。由于资料不足而暂时无法完成时，应保留“待补”状态并说明缺少什么证据或解释。
