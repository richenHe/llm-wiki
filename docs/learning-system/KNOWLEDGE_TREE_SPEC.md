# 知识树规范

知识树是动态深度的，不限制为两层或三层。任何节点都可以继续展开，直到该层已经是可以直接理解或练习的最小单元。例如“物理 → 力学 → 运动 → 速度 → 瞬时速度 → 导数解释”可以有六层；简单的操作说明可能只有两层。

## 建树规则

1. **先按学习意义分层。** 父节点必须能概括全部直接子节点。例如“品”可以概括“豆、奶、糖、器”，而“实体”不能解释这些知识为什么一起学习。
2. **同层保持同一尺度。** 同一组节点应回答同一级问题。例如“客、品、场”都是经营模块；不能把“咖啡豆”这种具体材料与“财务管理”放在同一层。
3. **短名必须可展开。** 节点可用一个字或一个词，但详情必须保存完整含义。例如“营”表示“运营”，打开后要说明运营包含排班、库存、活动和流程。
4. **顺序不是树结构本身。** 树回答归属，路线回答先学什么。例如“豆、奶、糖、器”都归属“品”，它们可以并列记忆，不必强行排成长链。
5. **关系不改变归属。** 一个节点只能有一个主要学习父节点，但可以有多个跨节点关系。例如“导数”主要属于数学，同时与物理中的“瞬时速度”建立关系点。

## 三层关系模型

系统不能把所有连线都当作父子关系，必须分开保存：

1. **结构层**：主要归属和组成部分，决定知识球从哪里逐层展开。例如“索引”主要归属数据库知识，“B树”可以是索引实现的组成知识。
2. **学习层**：严格前置、推荐前置、并列和下游用途，决定针对某个目标怎样学习。例如“比较大小”可以是“二分查找”的严格前置，“时间复杂度”可以是推荐深入。
3. **脉络层**：时间先后、问题—方案、方案替代、证据支持、证据反驳、版本变化和系统汇合，决定一段发展故事怎样成立。例如“全表扫描在数据增大后变慢”与“建立索引”构成问题—方案关系，但索引不是全表扫描的子节点。

同一对节点可以存在多种关系，但每种关系都要分别保存理由和证据。例如“导数”既可以是“瞬时速度”的严格前置，也可以是跨主题关联；界面根据当前是在看结构还是学习路线选择显示哪一种。

系统自动提取的关系先进入候选状态，至少记录来源位置、关系方向、可信程度和歧义说明。只有通过规则检查或用户确认后，才进入已确认状态。例如资料写“方法A与方法B经常结合使用”时，可以候选为系统组合，不能自动改写成“A取代B”。

## 路线对象

学习路线和发展脉络引用现有知识节点，不复制节点正文。路线至少记录名称、目标、适用范围、排序依据、步骤、步骤间理由、证据、未知项和版本。

学习路线允许根据不同目标生成不同顺序。例如“应试复习”可以先走高频考点，“从零理解”则先补严格前置；两条路线共享同一批知识节点。

发展脉络只有在资料能支持时间、问题—方案、证据积累或版本变化时才生成。例如公司制度只有当前操作步骤而没有历史资料时，系统不应虚构“制度演变史”。

## 完整性检查

每个父节点都要检查范围、遗漏、重复和尺度。比如“咖啡店经营”若有“客、品、场、服、营、财”却没有“增”，就缺少增长闭环；若同时存在“服务”和“顾客服务”，则可能重复。

关系和路线还要检查：主要父节点是否唯一、严格前置是否形成循环、路线能否到达目标、关系是否有依据、不同来源是否冲突，以及同一知识是否被复制成多个正文节点。例如“速度必须先学加速度、加速度又必须先学速度”形成前置循环，系统应标记错误并要求审校。

## 大规模输出原则

系统不会一次把整套初中知识的所有文字塞进画面，而是完整保存、逐层展开。全局只展示学科和核心主题，进入“数学”才加载其分支，再进入“代数”加载下一层。例如一棵有 20,000 个节点的树仍然完整，但第一屏可能只显示 12 个一级领域。
