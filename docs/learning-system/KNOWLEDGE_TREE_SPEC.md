# 知识树规范

知识树是动态深度的，不限制为两层或三层。任何节点都可以继续展开，直到该层已经是可以直接理解或练习的最小单元。例如“物理 → 力学 → 运动 → 速度 → 瞬时速度 → 导数解释”可以有六层；简单的操作说明可能只有两层。

## 建树规则

1. **先按学习意义分层。** 父节点必须能概括全部直接子节点。例如“品”可以概括“豆、奶、糖、器”，而“实体”不能解释这些知识为什么一起学习。
2. **同层保持同一尺度。** 同一组节点应回答同一级问题。例如“客、品、场”都是经营模块；不能把“咖啡豆”这种具体材料与“财务管理”放在同一层。
3. **短名必须可展开。** 节点可用一个字或一个词，但详情必须保存完整含义。例如“营”表示“运营”，打开后要说明运营包含排班、库存、活动和流程。
4. **顺序不是树结构本身。** 树回答归属，路线回答先学什么。例如“豆、奶、糖、器”都归属“品”，它们可以并列记忆，不必强行排成长链。
5. **关系不改变归属。** 一个节点只能有一个主要学习父节点，但可以有多个跨节点关系。例如“导数”主要属于数学，同时与物理中的“瞬时速度”建立关系点。

## 完整性检查

每个父节点都要检查范围、遗漏、重复和尺度。比如“咖啡店经营”若有“客、品、场、服、营、财”却没有“增”，就缺少增长闭环；若同时存在“服务”和“顾客服务”，则可能重复。

## 大规模输出原则

系统不会一次把整套初中知识的所有文字塞进画面，而是完整保存、逐层展开。全局只展示学科和核心主题，进入“数学”才加载其分支，再进入“代数”加载下一层。例如一棵有 20,000 个节点的树仍然完整，但第一屏可能只显示 12 个一级领域。
