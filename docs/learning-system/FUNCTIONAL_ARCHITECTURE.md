# 功能框架

## 1. 知识球

全局地图用节点和线构成镂空球壳，点击节点后进入聚焦模式。聚焦模式保留当前节点、直接子节点和必要的兄弟上下文。例如点击“运动”后，球面重点显示“位移、速度、加速度、运动图像”，其他学科只保留低干扰背景点。

## 2. 位置路径与目录

左上面板提供“路径”和“目录”两种看法。路径回答“我现在在哪里”，目录回答“这一部分还有什么”。例如路径显示“高中物理 → 力学 → 运动 → 加速度”，点击“力学”即可返回上一层；目录可以独立滚动查看几十个子节点。

这条位置路径只表示主要归属，不表示历史先后、因果关系或学习前置。例如“导数”在位置路径中属于数学，即使物理中的“瞬时速度”需要导数，它也不会因此被移动到物理目录。

## 3. 学习路线与发展脉络

用于记忆目录结构的同级路线只串联真正的同级兄弟，并区分推荐顺序和并列记忆。例如“客、品、场、服、营、财、增”同属“咖啡店经营”，可以组成同级路线；“豆、奶、糖、器”属于“品”的下一层，不会混进这条路线。

系统还可以根据用户目标建立跨分支学习路线。例如学习“瞬时速度”时，路线可以从物理中的“平均速度”跨到数学中的“导数”，再返回“瞬时速度”；跨分支不会改变任何节点的主要归属。

发展脉络是另一类可选路线，用于展示问题、观点、技术或制度怎样演变。它必须标明排序依据是时间、问题—方案、证据积累还是版本变化，并为每一步保存来源和关联理由。例如数据库主题可以展示“全表扫描在大数据量下变慢 → 使用索引缩小查找范围 → 查询更快但写入成本增加”。

用户选择路线后，知识球只高亮涉及的节点与关系，路径面板显示当前步骤、上一步的承接理由和下一步要解决的问题。退出路线后恢复完整知识结构。例如跨到“导数”节点学习后退出路线，知识球仍把导数放回数学分支。

## 4. 跨节点关系

跨主题关系默认只显示少量紫色关系点，避免线条爆炸。悬停显示目标、路径和关联原因，点击后平滑进入目标上下文。例如“加速度”关联“导数”时，只显示一个关系点；点击后球面移动到“数学 → 微积分 → 导数”。

关系不能只保存一条没有含义的连线。系统至少记录关系类型、方向、自然语言理由、来源、可信程度和确认状态；自动提取但尚未确认的关系应与已审校关系明显区分。例如两份资料都提到“缓存”和“数据库”，只能形成候选关联，只有资料明确说明缓存减少重复读取后，才能标成系统组合关系。

## 5. 知识详情

详情按需打开，包含精华解释、来源、前置知识、下一层和掌握程度。例如“加速度”详情先显示“速度变化得有多快”，再显示教材章节和“速度”这个前置知识。

## 6. 学习与进度

学习模式要求学习者主动讲解，答案会保存在当前项目中并更新练习状态。例如输入“加速度表示单位时间内速度的变化量”并提交后，该节点会记录一次自我讲解。

## 7. 大规模知识处理

数据层保留完整知识，界面层只绘制当前需要的一部分，这叫“可见窗口”。例如知识库有 50,000 个节点时，搜索和目录仍能访问全部节点，但球面一次只绘制约 24–96 个相关节点，避免卡顿和文字重叠。
