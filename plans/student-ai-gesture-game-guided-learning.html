阶段 1：运行游戏并理解实时循环

解决的问题：确认源码、依赖、浏览器和游戏入口连通。Vite、npm 属于辅助工具；游戏循环属于核心原理。

原理门：为什么画面会动

屏幕只显示离散帧。最直接的“按一次移动固定距离”会因机器帧率不同而变快或变慢。通用办法是每帧计算经过时间，更新所有状态，再重画。可观察中间结果是玩家位置、当前场景和帧间隔；换任何引擎仍需同样的时间循环。

技术实现流

浏览器开始一帧 → 读取键盘/鼠标/触摸 → 按经过时间更新状态 → 处理碰撞和死亡 → Canvas 绘图 → 请求下一帧

AI 保证同一循环消费所有输入；用户看到菜单、能进入战斗、飞机持续移动才算成立。只有速度随设备变化时才深入时间步长代码。

工具说明

Node.js 让构建程序在命令行运行；npm 按 package.json 准备依赖；Vite 把模块启动成开发网页并打包。输入是源码和依赖清单，输出是本地网址或 dist。三者都不负责飞机移动规则。

你实际怎么做

cd D:\project\ai-gesture-game-sky-blaster
npm install
npm run dev -- --host 127.0.0.1 --port 5174
通过：终端显示网址，浏览器出现飞机游戏，能进入战斗并移动。终端成功只证明服务器运行；实际画面才证明入口、循环和绘制成功。
常见失败：端口占用时看 Vite 实际打印的新端口；页面空白先看浏览器控制台，不要反复安装依赖。

教师讲解：游戏循环像老师不断点名：每轮先收集输入，再更新全班状态，最后把结果写到黑板。

停止点：能稳定进入并玩一局后再进入阶段 2；本阶段不做摄像头。

阶段 2：把参考项目变成自己的战斗机制

解决的问题：不只换标题，而是改变真正影响玩法的规则。游戏状态机与反馈是核心；素材是可替换实现。

原理门：规则与表现必须分开

只加亮光不能修复距离太短或奖励无效。把数值、碰撞和特效混在绘图函数里，会让一次修改破坏多个系统。通用原则是先由规则层决定“发生什么”，再由表现层决定“怎样让人感受到”。中间结果包括武器类型、伤害、炸弹库存、敌弹清除和爆炸时间线。

技术实现流

输入事件 → 规则判断射击/技能/炸弹 → 更新生命、伤害、库存和掉落 → 生成特效事件 → 绘制闪光、冲击环、粒子与震屏

例如炸弹上限 3 先由库存规则限制；释放后减 1，拾取最多补到 3；全屏爆炸只是结果的视觉证据。

Canvas 2D 是什么

它是浏览器即时绘图板，接收坐标、颜色、图像和路径，输出一帧像素。它不理解散弹或光剑，含义由规则定义。本项目用它画战机、弹幕、首领、爆炸和界面。

当前真实结果

  • 中文界面；战机和炮台全部解锁。
  • 炸弹上限 3，可拾取补充；释放时清敌弹、伤害敌人并播放全屏爆炸。
  • 散弹与光剑距离已延长；握拳后张掌可立即触发炸弹。
  • 火力核心最多 3 级，不再掉落独立射速强化；死亡会清除本局火力、临时武器、护盾、炸弹和玩家弹幕。
  • 普通敌人不再一碰即死；Boss 血量提高，并用 66% 与 33% 两道阶段门保证三个阶段都会实际发生。
  • 四章使用四套敌机阵营造型，每章五关再用 1–5 条发光识别标记区分；第 5、10、15、20 关仍使用各章独立 Boss。

图像生成与图集切片是什么

图像生成工具先产出一张 4 列 × 3 行的透明敌机图集：列代表四章阵营，行代表截击机、重型炮舰和支援机。Canvas 绘制时只截取对应格子，例如第 7 关的治疗机取“第二列、第三行”，再加第 2 条关卡标记。图像工具负责造型素材，不负责血量、碰撞和 Boss 阶段。

通过：炸弹、武器、首领和游戏规则测试通过，实际画面能看到爆炸。测试证明预设逻辑，不证明视觉一定符合审美；后者必须看画面。
排错：库存不变先查规则；库存减少但无爆炸查表现；很亮但敌人不掉血仍是规则问题。
停止点：键鼠或触摸玩法成立后再接手势；MediaPipe 不决定伤害。

阶段 3：摄像头帧怎样变成 21 个点

解决的问题：从像素中得到可计算的手部结构。摄像头接口与 MediaPipe 属于核心技术。

原理门：像素不能直接当手势

肤色分割或固定模板会受光线、肤色、距离和旋转影响。可迁移原理是用训练好的模型把一帧像素转换成固定编号的骨架点，再由自己的规则解释。中间结果是 21 个 0–1 坐标和“是否找到手”；替代模型只要输出同类结构，后续可保留。

技术实现流

点击体感 → 浏览器请求前置摄像头 → 隐藏 video 接收视频 → 每 66ms 取一帧 → 模型输出最多一只手的 21 点 → 显示找到手或等待手

过程在浏览器运行。模型与运行组件已经放在 public/mediapipe 中，并随游戏发布，不再访问 Google 与 jsDelivr；视频不上传。AI 要处理拒绝权限、模型超时和关闭后停止摄像头。

MediaPipe 是什么

它是训练好的本机视觉组件，接收视频帧，输出手腕、关节和指尖坐标。没有它就要自行训练模型。它不决定飞机去哪或何时炸弹；例如第 8 号点是食指尖，但它的游戏含义由我们定义。

左上角按钮默认“体感关闭”，不显示摄像头小窗。点击并允许摄像头后应显示开启；手离开画面时游戏继续，只停止体感位置输入。

通过：摄像头轨道建立、模型加载、手进入后持续产生关键点。自动化已验证按钮与隐藏视频布局；真人关键点仍需真机验证。
排错：立即失败先查 HTTPS 和权限；开启但找不到手，再查光线、完整入镜、模型请求和置信度。
停止点：只确认“视频 → 21 点”，不在本阶段调炸弹动作。

阶段 4：把 21 个点变成移动和炸弹

解决的问题：把不稳定视觉证据转换成可预测输入。这是学习者拥有的判断层。

原理门：几何、时间与状态缺一不可

原始坐标会抖；动作转换中还会短暂丢手。通用机制是先用手指与手腕相对距离分类，再平滑位置，并由状态机记住动作顺序。只有技能需要持续时间；大招采用“拳头出现过，再看见张掌”的边沿触发。中间证据是候选动作、持续毫秒数、大招就绪状态、技能进度、原始与平滑坐标。

决策流

食指单独伸出 → 平滑坐标 → 镜像横向 → 中央有效区拉伸到全屏 → 写入战机目标；不是该手势或没有手 → 立即清除移动输入。握拳 → 记录大招就绪；随后张掌 → 立即释放一次炸弹。拇指与食指捏合 2.5 秒 → 释放战机技能。

AI 必须保持键鼠、触摸和体感共用同一输入状态，手丢失时不能让战机继续冲向旧目标。

自己的规则层做什么

动作解释器（代码中叫 GestureInterpreter）接收关键点和时间，输出候选、确认动作、位置、大招与技能事件；坐标契约将中央区域映射到画布。它不获取摄像头、不画爆炸。横向 15%–85%、纵向 25%–75% 被扩展到全屏，手不必触碰镜头边缘。

通过：分类、拳转掌只触发一次、短暂丢手容错、2.5 秒技能和有效区映射均有测试；真人应能用单指移动，其他动作不拖着飞机继续走，握拳后张掌可靠放炸弹。
排错：手可见但飞机不动看映射；容易断连看手是否出镜；乱放炸弹看候选和持续时间，不先改特效。

已有理解证据：你指出“缩小界面框不能扩大镜头视野，反而更容易出框”，正确区分了界面大小与摄像头物理视野。

停止点：动作控制现有游戏后再做手机交付；不新增云端识别。

阶段 5：手机布局、HTTPS 与国内外双部署

解决的问题：让手机安全打开并主动授权摄像头。响应式布局是核心原则；Vite、Vercel 与国内静态托管是辅助工具。

原理门：手机不是缩小版电脑

手机屏幕窄、刘海区域不同、按钮需要足够大，而且摄像头通常要求 HTTPS。简单等比缩小会让按钮难点、画布留边。通用原则是画布跟随可视区域，控件使用安全边距和最小触控尺寸，只在用户点击时申请摄像头。

技术实现流

Vite 构建静态网页 → Vercel 与 CloudBase 分别发布 → 手机从 HTTPS 地址加载游戏 → 用户点击左上角开关 → 浏览器授权 → 前置镜头与 MediaPipe 工作

Vercel 收到网页文件，不收到视频。摄像头画面为 1×1 且透明，只保留开关。

部署工具是什么

Vercel 与腾讯云 CloudBase 静态托管都接收构建文件并返回 HTTPS 网址，不运行战斗也不识别手。Vercel 保留为海外版本；国内首选 CloudBase，因为它支持控制台上传和命令行部署，并提供默认 HTTPS 域名。EdgeOne Pages 更接近 Vercel，但大陆长期自定义域名仍涉及备案， 不作为第一次验证的最短路线。

打开国内 CloudBase 地址；打开海外 Vercel 地址。CloudBase CLI 3.8.0 将 dist 的 8 个文件上传到免费体验环境 train-d0g0jkstu8c07205e；主页、手部模型和 WASM 均通过 HTTPS 返回 200。部署成功只证明文件可访问，不能替代真人摄像头验收。

已通过：CloudBase 页面标题为“天际手势战机”，游戏画布、隐藏视频和体感开关存在；主页、模型与 WASM 返回 200。390×844 时画布铺满，按钮约 97×44，隐藏视频 1×1、透明。
