先做一个可控、可演示、可迁移的机器人头

它会盯住学生，也知道什么时候必须停下

第一件作品不是一辆容易撞桌子的全功能小车，而是双舵机云台上的“桌面守护者”：视觉模块找到一个学生或目标，机器人头左右、上下跟随；看到举手时点头，看到握拳时摇头并改变灯光或声音；目标消失后停止追赶、进入搜索，重新出现后恢复锁定。

最小通过条件：目标进入画面后能平稳回到中心区域；不会持续抖动；目标消失后在设定超时内停止；机械角度受限；三种互动可连续演示 5～10 分钟。

新手难度中等；首个难点是供电与控制调参

为什么这个项目比“拼一辆遥控车”更值得学

它把当代具身智能的必要基础压缩成可见闭环：感知环境、形成结构化观察、选择行为、驱动机构、再观察动作结果。“具身”在这里指智能不仅回答文字，还通过身体动作影响环境；例如机器人头转向后，目标在画面中的位置发生变化，这个新位置又决定下一次动作。将来即使增加视觉语言模型，稳定运动仍离不开这条闭环。

原理先于摄像头和开发板

机器人不是“看到人就转”，而是在不断缩小误差

真正的核心，是把视觉观察转换成受限动作，再用动作后的新观察纠正自己。这叫闭环控制：结果会回来影响下一次决策。

为什么不能把目标坐标直接当舵机角度

根本约束：视觉坐标会抖，舵机有惯性和机械间隙，电源也会波动。若“目标右移 1 像素就让舵机动一次”，机器人会在中心附近不停左右抽动。若目标消失还沿用旧坐标，它会继续转向危险位置。

标准化观察

视觉模块给出目标中心 X、Y、宽高和编号。行为层把不同分辨率统一成约 -1 到 1 的位置。例如 X 为 0 表示画面中心，+0.4 表示目标在右侧。这样换摄像头分辨率也不用重写控制规则。

常见失败：坐标方向与舵机方向相反。测试：把模拟目标移到右边，命令方向必须让下一帧误差变小。
误差与比例控制

误差是“目标位置减去画面中心”。比例控制用误差大小决定动作大小：离中心越远，转得越快；靠近中心，动作越小。

error = targetX - centerX command = Kp × error
Kp 是反应强度。太小会跟不上，太大会来回摆。第一版只学比例控制，不先堆完整 PID。
死区与平滑

中心附近划一块“不必动作”的区域，叫死区。例如标准化误差在 ±0.08 内保持不动，可防止舵机追逐每个微小抖动。平滑则让新观察与过去值结合，避免命令突变。

权衡：死区太大时机器人显得迟钝，太小时一直抖；用中心误差和每秒反向次数判断。
行为状态机

机器人必须知道自己处于搜索、已锁定、响应动作还是丢失安全状态。状态决定同一观察能做什么。例如锁定状态收到“举手”可点头，丢失状态则禁止继续跟随，只能慢速搜索或停住。

建议状态：SEARCH → TRACK → RESPOND → TRACK；无有效目标超过 500 毫秒进入 LOST_SAFE。
物理安全边界

软件命令必须经过角度、速度和超时限制。供电也属于系统原理：舵机启动瞬间需要较大电流，若和控制板共用弱电源，电压下降会让开发板重启。

例子：初始机械角度先限制在 30°～150°；舵机单独使用足够的 5V 电源，但控制器与舵机电源必须共地。
必须理解

观察、误差、比例控制、死区、状态、动作限制和反馈如何循环；这是机器人真正“会动”的原理。

调试时再深入

平滑系数、滞回、串口时序、舵机脉宽、电压跌落；出现抖动、延迟或重启时再查。

现在不要深挖

从零训练视觉模型、完整 PID 推导、运动学和自主导航；它们会延迟第一件安全作品。

原理检查：如果换掉所有品牌名称，你仍能说清“画面变成目标坐标，坐标产生误差，状态选择动作，受限命令驱动电机，新坐标再纠正命令”，说明你掌握了底层路线。

责任边界

视觉模块负责输出目标数据，开发板负责实时读取与驱动，编码 AI 负责创建工程和测试，你负责定义可见行为与安全规则。例如你要求“目标短暂遮挡 300 毫秒时先保持，但超过 500 毫秒必须停”，这属于你拥有的丢失策略，而不是某个摄像头自带功能。

主路线学闭环，前沿分支只试理解能力

原理技术位置投入价值何时重评
边缘视觉输出结构化目标当前主流本地运行、延迟可控、没有持续云费用，适合课堂与机器人控制。替代模块必须同样可购、可离线并输出坐标与身份信息。
状态机、比例控制、死区与安全限制当前主流基础从云台到移动机器人都复用，是模型升级也不会消失的控制能力。复杂运动出现比例控制无法解决的稳态或动态问题时，再学 PID、轨迹规划。

前沿分支最多半天：允许大模型读取“已识别的人与动作”并生成一句台词，但实时跟随仍由本地确定性闭环控制。网络断开或模型失败时，机器人照常跟随和安全停止。

工具只学到够用

  • 视觉模块：会选模型、学习目标、切换 I2C/UART、读取 X/Y/宽高/ID、识别无目标和通信失败。
  • 控制板：会编译上传、看串口日志、配置通信和两路舵机、恢复连接失败。
  • 舵机与供电：会断电接线、检查电压、共地、校准安全角度，不需要先学电机内部制造。
  • 暂不学习自训模型、SLAM、机械臂运动学和完整自主导航。

视觉和驱动可替换，你拥有行为

你的核心模块叫 behavior-engine

它接收标准化观察，不依赖某个摄像头；它输出受限命令，不依赖云台还是车轮。这一层包含机器人“如何表现”的真正判断。

输入契约：{ targetId, xNorm, yNorm, sizeNorm, visible, gesture, timestamp }

拥有的规则：平滑、死区、比例增益、目标选择、SEARCH/TRACK/RESPOND/LOST_SAFE 状态、丢失超时、行为优先级。

输出契约：{ panDelta, tiltDelta, mode, signal, reason }

安全边界：角度与速度钳制、陈旧数据拒绝、目标丢失停止、通信错误回退。

必须附带：坐标模拟器、配置、状态转移测试、边界测试和结构化诊断日志。

迁移到移动宠物车时，behavior-engine 仍产生“向左、向右、跟随、停止”等高层命令；只把云台适配器换成左右轮速度适配器。迁移前必须为移动底盘新增距离传感和防撞安全层，这属于新执行器的必要边界，不是推翻核心。

可见问题第一处可能异常证据与恢复
目标向右，机器人却向左越转越远坐标或执行器方向看误差符号、命令符号和下一帧误差；只反转适配器方向。
中心附近不停左右抖死区、增益或机械间隙看每秒反向次数；先扩大死区或降低 Kp，再检查舵机。
舵机一动，控制板重启供电串口出现启动信息或掉线；停止动作，改用足够的独立舵机电源并共地。
目标消失仍继续转观察时效与 LOST_SAFE看最后数据年龄；超过 500 毫秒必须停止，修复后用遮挡测试。
硬件安全底线：断电接线；首次只接一个舵机；起始角度限制 30°～150°；不要用开发板的弱 5V/3.3V 引脚直接带两个舵机；独立电源必须与控制板共地。具体电压和引脚以实际型号资料为准，未确认前不要猜接。

最快学习路线

第 0 阶段｜前两小时：无硬件模拟

新对话先创建 behavior-engine、坐标模拟器和诊断界面。拖动屏幕里的目标点，观察误差、命令和状态；目标进入死区后命令归零，隐藏超过 500 毫秒进入 LOST_SAFE。通过后你已理解闭环，不必等快递。

第 1 阶段｜第一天：只读视觉，不接舵机

安装 Arduino IDE 2.x 或实施 AI 选择的兼容命令行工具、ESP32-C6 板卡支持和 DFRobot 官方库。只连接视觉模块和控制板，在串口稳定看到 ID、X/Y、宽高和“无目标”。此时任何舵机都不动。

arduino-cli version arduino-cli board list

若选择命令行路线，第一条应显示版本，第二条在 USB 连接后应显示串口与板卡。若没有命令，安装 Arduino IDE/CLI 后重新开终端；若无板卡，先检查数据线和驱动，不要改行为代码。

第 2 阶段｜单轴到双轴

断电接一个舵机和独立电源，先验证安全角度与方向，再接目标 X 轴跟随；稳定后才增加 Y 轴。通过标准是目标进入中心死区后停止，遮挡后安全停。

第 3 阶段｜第一周：加入人格化行为

加入举手点头、握拳摇头和灯光/声音反馈，并写清优先级：安全停止高于搜索，响应动作高于普通跟随，响应结束回 TRACK。连续运行 10 分钟且无重启、碰撞或限位冲击才通过。

迁移测试｜移动宠物车

先在轮速模拟器复用 behavior-engine，换执行器适配器；然后新增防撞传感与急停，再上实车。不要让“能在云台上工作”被误解为“可直接安全驱动车轮”。

3 · 有意义的行为修改
增加“守护者人格”：目标举手稳定 400 毫秒后点头一次，握拳稳定 400 毫秒后摇头并改变灯光；响应期间暂停普通跟随，结束后回 TRACK；目标丢失或通信错误立即高优先级进入 LOST_SAFE。先列出状态和优先级，再修改 behavior-engine、模拟器、日志和测试，最后在实机上逐项低速验证。
4 · 根据证据诊断
当前症状是“跟随时中心附近不断抖动”。不要直接换硬件或随意改参数。依次检查原始 X/Y、标准化与平滑误差、死区、Kp、命令方向与幅度、实际舵机角度、每秒反向次数、电源重启迹象；找到第一项异常，区分视觉噪声、控制调参、机械间隙和供电。先在模拟器重现与修复，再低速上实机，报告修复前后数据。
5 · 迁移到移动宠物车
保留 TargetObservation、behavior-engine、状态机、诊断和测试，把执行器适配器迁移到移动宠物车模拟器。把水平控制量映射为左右轮速度差，但先新增距离传感、速度上限、急停和目标丢失停止；没有这些安全层不得驱动实车。列出原样复用、适配和新增安全模块，并证明同一观察序列在云台和小车上得到一致高层状态。

先安全，再稳定，最后才是“震撼”

完成标准与真正学会的标准

  • 模拟器：目标进死区后命令归零；无目标超过 500 毫秒进入 LOST_SAFE；边界角度永远不越界。
  • 实机：目标能被重新拉回中心附近，不持续振荡；运行 5～10 分钟无重启、过热、线材拉扯和限位撞击。
  • 举手、握拳和丢失三种行为优先级正确；快速闪过一帧不会触发响应。
  • 日志能区分视觉、通信、行为、执行器和供电问题，AI 不能只用“识别不准”概括。
  • 移动小车迁移先通过模拟器和安全设计，不把云台代码直接烧进有碰撞风险的底盘。

五项原理掌握检查

  1. 不用品牌名解释观察—误差—动作—反馈闭环。
  2. 预测增大 Kp 或扩大死区分别会发生什么。
  3. 从中间日志定位方向反转、抖动或丢失不停止属于哪一层。
  4. 写出新视觉模块和新执行器分别要满足的契约。
  5. 加入一个新行为，并把 behavior-engine 迁移到移动平台模拟器。
