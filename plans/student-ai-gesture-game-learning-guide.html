天际手势战机

理解“摄像头中的手怎样变成战机行为”，并能判断故障发生在摄像头、识别、动作规则、输入映射还是游戏表现。

最终要做出的结果

在电脑或手机浏览器打开纵向飞机射击游戏：键盘、鼠标或触摸仍能玩；用户主动开启左上角“体感”开关后，单独伸出食指控制战机，握拳后张开手立即释放全屏炸弹，拇指与食指捏合 2.5 秒释放战机技能。炸弹最多携带 3 个，并可拾取补充；火力核心最多 3 级，死亡后本局强化清空。

最小通过条件：能进入战斗；飞机能移动、射击并切换武器；炸弹库存遵守 0–3 上限；体感关闭时不请求摄像头；手机页面无横向溢出；公网 HTTPS 页面可打开。

国内作品：CloudBase 公开地址；海外备份：Vercel 公开地址。两个地址发布同一架飞机游戏，不覆盖原来的 Grasp。

边界：电脑模拟 390×844 只能验证布局，不能替代真实 iPhone 或 Android 的摄像头权限、镜头视角和性能测试。

实时游戏循环

想要：飞机、敌人、子弹持续运动。限制：屏幕只会显示一张张离散画面。只在按键时重画会让世界停住；每次固定移动又会因电脑快慢改变速度。原理：每帧读取经过时间，用“速度 × 时间”更新状态再绘制。可观察玩家坐标、敌人坐标和帧间隔；换引擎后仍成立。

手部关键点

想要：摄像头看见手就能控制。限制：像素没有“手腕”和“指尖”的含义。肤色或固定轮廓会被光线、距离和旋转破坏。原理：训练好的视觉模型把图像转换成结构化关键点。本项目读取 21 个点，而不是让模型直接决定游戏行为。

动作与时间状态

想要：握拳后张掌立即且只释放一次炸弹。限制：转换时可能短暂像捏合或丢失一帧。若“只看当前一帧”，张掌时已经不知道前面是否握过拳。原理：状态机先记住“看见过拳”，再等待下一次张掌边沿；短于 350 毫秒的丢手仍保留这段记忆。技能采用另一条规则：捏合持续 2.5 秒才触发，避免与大招冲突。

坐标映射

想要：手不碰镜头边缘也能飞遍屏幕。限制：原样映射会迫使手移动到镜头边缘并丢失。原理：把中央有效区重新拉伸到整个游戏范围。本项目将横向 15%–85%、纵向 25%–75% 映射成全屏控制区。

无代码技术实现流

浏览器取得前置摄像头，视频留在本机
→ 约每 66 毫秒取一帧交给手部模型
→ 模型返回最多一只手的 21 个归一化坐标
→ 规则层判断单指、手掌、拳头、捏合等候选
→ 状态层记住拳转掌顺序，并计算捏合技能进度
→ 只有单指手势的位置才会镜像和放大为战机目标坐标
→ 输入层统一体感、键盘、鼠标和触摸
→ 游戏循环更新飞机、子弹、敌人、掉落物和炸弹库存
→ Canvas 2D 绘制最新状态，下一帧继续反馈

运行位置：识别、规则、游戏和绘图全部在用户浏览器；Vercel 与 CloudBase 只通过 HTTPS 发送网页文件，不处理摄像头视频。

实施边界：MediaPipe 只提供关键点；稳定时间、有效区、武器距离和节奏属于项目自己的可编辑层。体感失败时必须允许键鼠或触摸继续玩。

何时打开代码：只有真实症状需要定位时。例如“手在中央但战机到不了右边”才查看坐标映射；理解整体流程不必先读语法。

工具无关架构

输入提供者（摄像头 / 键盘 / 鼠标 / 触摸）
        ↓
标准化输入（位置、射击、技能、炸弹）
        ↓
自己的判断层（手势几何、稳定时间、状态与映射）
        ↓
游戏状态机与战斗规则
        ↓
表现层（Canvas、粒子、闪光、震屏、声音）
        ↓
观察路径（状态提示、测试、浏览器错误、真人体验）

换手部模型时只替换“视频帧 → 关键点”；换渲染引擎时只替换表现层。普通工具故障不应推翻整条架构。

必须理解

关键点、动作规则、时间稳定、坐标映射、统一输入和游戏循环。

调试时再深入

置信度、滤波系数、碰撞细节与移动端性能。

现在不用深挖

从零训练模型、手写图形底层、后端账号系统。

为何不加 Phaser、Babylon.js 或 Blender：当前 Canvas 2D 战斗循环已经满足飞机游戏；三维引擎和建模不会改善当前玩法或体感，反而增加迁移成本。

真正值得掌握的成果

不是背 MediaPipe 接口，而是掌握“手部点怎样变成稳定游戏输入”的判断层。

输入 21 个关键点、时间戳、手是否可见
自己的规则 单独食指移动、拳转掌大招、350 毫秒短暂丢手容错、捏合 2.5 秒技能、位置平滑、中央有效区
输出 战机目标坐标、炸弹事件、技能事件
观察 体感状态、规则测试、映射测试、真人重复动作
迁移 将同一输入协议接到赛车或节奏游戏
