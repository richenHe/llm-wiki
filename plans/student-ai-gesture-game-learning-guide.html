学生抬手，屏幕中的魔法立刻回应

为什么这类游戏能吸引小学生

关键不是“加积分”，而是把身体动作变成即时、可见、可掌控的结果。比如学生握拳后，能量球立即变亮，这个亮度变化就是动作与结果之间的直接反馈；敌人分三波逐渐加快，则提供短目标和适度挑战。2024 年的教育游戏综述与研究把即时反馈、主动参与、挑战、选择权与投入度反复联系起来，但也提醒：有趣不等于自动学会知识。因此课堂上应让学生解释一次“为什么误判不会施法”，而不只比较分数。来源见文末证据表。

原理先于产品名称

摄像头没有看到“魔法”，它只看到不断变化的像素

真正值得学习的技术，是怎样把含噪声的连续图像，逐步压缩成稳定、可预测的游戏事件。

为什么不能“识别到拳头就马上蓄力”

根本约束：每帧图像都会受光线、遮挡、运动模糊和手指角度影响。若一帧结果直接控制游戏，手只是路过拳头形状也可能触发。这个失败迫使系统先形成结构化表示，再跨时间积累证据。

真实输入连续像素
内部表示21 个手部点
候选判断动作＋可信程度
时间证据稳定时长
离散决策统一事件
可见反馈施法与音效
结构化表示

复杂像素先被压缩成手腕和手指关节坐标。坐标让后续规则不必重新理解整张图片。例如食指尖的横向坐标从 0.2 移到 0.8，可以直接映射为准星从左向右移动。

常见失败：左右镜像反了。测量方法：手向右移动时，标准化后的横坐标必须按设计方向变化。
分类与几何

系统可以接收模型给出的“握拳候选”，也可依据关键点关系补充自定义动作。候选不是最终命令，只是一次证据。例如模型返回“Closed_Fist，0.91”，表示这一帧较像拳头，不表示已经允许施法。

可迁移点：以后换识别器，只要还能给出坐标、候选和时间，后面的规则不变。
时间稳定

要求相同证据持续一段时间后才触发，这叫时间稳定处理。示例起点是持续 400 毫秒才进入蓄力，释放后冷却 600 毫秒；这些是待实测参数，不是假装适合所有电脑的事实。

权衡：400 改成 700 毫秒会减少误触，却让学生感觉更慢。用误触次数和输入到反馈的延迟共同判断。
状态机

同一个张手动作在不同阶段含义不同：等待状态可作为“准备”，蓄力状态才是“释放”。把有限阶段和允许的转换写清楚，就不会在冷却时重复施法。

例子：等待 → 蓄力 → 释放 → 冷却 → 等待；任何非法转换都记录在诊断栏。
并行节奏

识别和画面渲染的耗时不同。若重识别堵住主线程，动画就会停顿。Web Worker 是浏览器里的后台工作线程，可把同步识别移开；主线程只消费结果并绘制游戏。

证据：Google 官方网页文档明确说明视频识别调用会阻塞界面线程，并建议使用 Worker。比较指标是帧时间，而不是只看识别正确率。
必须理解

表示、候选、连续证据、统一事件、状态机和反馈如何连接；这是你创造动作的能力。

调试时再深入

可信程度校准、镜像、帧率波动、Worker 消息频率；出现跳动或卡顿时再查。

现在不要深挖

从零训练手部模型、完整神经网络损失函数、复杂着色器；它们不改善第一件作品的核心判断。

掌握原理的判断：不用任何产品名，也能解释“图像先变成坐标，坐标形成候选，连续证据产生事件，状态机决定是否施法”。做到这一点，工具换掉仍然会做项目。

用户、AI 和工具各自负责什么

视觉工具负责把帧变成数据；游戏引擎负责稳定绘制；编码 AI 负责创建文件、测试和修复；你负责定义“什么动作算有效、什么时候反馈、怎样才算好玩”，并根据诊断证据要求修改。例如你决定“张手不是立刻发射，而是只有在蓄力后才发射”，这就是你对核心行为的创造，不是给模板换颜色。

稳定主路线与一个受控前沿分支

原理技术位置投入价值何时重评
手部关键点与本地实时识别当前主流官方网页实现可直接运行，坐标能迁移到游戏、机器人和无接触交互。新方案在相同设备上显著降低延迟、提升遮挡鲁棒性，并保留结构化输出。
时间稳定、状态机、事件解耦当前主流基础它们解决噪声、冲突和复杂行为，是换模型也不会淘汰的系统能力。不会因某个工具更新而失效；只会换具体算法。
视觉语言模型实时生成玩法规则前沿实验能理解更开放的动作描述，但延迟、成本和可重复性不适合第一版课堂控制。当浏览器或本地设备有可复现的低延迟实现、结构化输出和确定性回退时再测。
前沿不等于更值得先学。本路线只给前沿分支 2 小时：让模型为动作候选加一句解释，但不允许它控制实时施法。实验失败时删除这层，主游戏仍完整。

对标项目不是最终作品

  • Google Gesture Recognizer 网页指南：学习如何从视频得到关键点和手势；不教时间稳定和游戏规则。
  • Google Worker 示例：学习把识别移出界面线程；不教完整课堂体验。
  • Phaser 官方文档与示例：学习场景、对象、动画和输入；不负责识别。

工具只学到够用

  • MediaPipe：会初始化、读取坐标与可信程度、识别权限/模型加载错误、知道何时换适配器。
  • Phaser：会运行场景、接收事件、替换自己的素材、调一条玩法规则、查看帧率。
  • Vite / TypeScript：会启动、检查、构建，知道 Worker 与主线程的边界。
  • 暂不学习模型训练器、Phaser 插件大全和多人服务器；它们不是当前瓶颈。

复用基础设施，自己拥有判断

你的核心模块叫 gesture-engine

它不识别像素，也不画粒子；它专门把任何识别器的易抖动结果，变成稳定、可测试、可迁移的动作事件。

输入契约：{ landmarks, candidate, confidence, handedness, timestamp }

拥有的规则：坐标归一化、动作几何、稳定时间、冲突优先级、释放条件、冷却。

输出契约：aim、charge-start、cast、cancel，以及产生事件的证据。

必须附带：配置文件、输入适配器、模拟帧、单元测试和诊断轨迹。

第二件作品把它迁移到“手势节奏挑战”：识别和稳定模块原样复用，只把 cast 的消费者从攻击敌人换成命中节拍。这证明你拥有的是技术路线，而不是一份守城代码。

画面正常却没有骨架视觉提供者查模型加载、运行模式和输入尺寸；不要先改游戏。

环境检查

第一阶段｜前两小时：复现机制

AI 先创建键盘可玩的单场景游戏、统一输入接口和诊断栏。按键移动、蓄力、释放都工作，完整打完一局即通过。此阶段学的是事件和状态，不被摄像头问题拖住。

第二阶段｜第一天：接入自己的动作

接入 MediaPipe Worker，把真实手部坐标映射到准星，把拳头和张手通过 gesture-engine 产生事件。使用你自己的动作和规则，不提交官方示例。三种输入连续完成一局即通过。

第三阶段｜第一周：修改核心行为

加入“完美蓄力”：稳定 400 毫秒开始，保持 1.2 秒获得穿透，手消失立即取消，并用测试覆盖误判与冷却。参数要根据实际课堂体验调整，不能把示例数字当真理。

迁移测试｜第二件作品

保留 gesture-engine，做一关手势节奏挑战。只重写游戏消费者与玩法状态。若同一输入测试能在两个游戏中产生相同事件，迁移通过。

第一失败点：识别放在主线程导致卡顿，或摄像头权限被拒绝。回退方案始终是键盘适配器；它让教学与游戏开发继续进行，同时单独修复视觉层。

1 · 第一阶段实施
阅读这份 HTML，把它视为已经确认的技术学习教程和项目实施说明。先检查当前目录、Node.js、浏览器与摄像头，不要重新做整套技术选型。从第一个尚未完成的阶段开始：先创建 Phaser 4.2.1 + Vite 8 + TypeScript 项目，实现键盘可玩的 60～90 秒“AI 体感魔法守城”核心循环、统一输入事件接口和可关闭诊断栏；再接入 MediaPipe Tasks Vision 1.0.1，并把视频识别放入 Web Worker。

必须保留：输入适配器 → gesture-engine → 游戏状态机 → 表现层，以及原始输入 → 候选 → 稳定证据 → 事件 → 游戏状态的观察路径。AI 负责创建文件、安装项目依赖、写代码、运行测试、打开实际页面并修复范围内失败；不要让我手写代码。每阶段报告可见结果、原理对应、验证证据和未确认项。不要加入账号、数据库、联网排行、多人或模型训练。
2 · 有意义的行为修改
在不改变架构的前提下增加“完美蓄力”：拳头连续稳定约 400 毫秒才开始；保持到 1.2 秒时能量变色并获得穿透；中途不确定或手消失就取消；释放后冷却约 600 毫秒。先说明每条规则属于 gesture-engine 还是游戏状态机，再修改、补测试和诊断字段。参数只是起点，请根据页面实测说明怎样调得更灵敏或更稳。
3 · 根据证据诊断
当前症状是“握拳后偶尔没有蓄力”。不要猜着改阈值。依次检查摄像头帧率、Worker 识别耗时、关键点、候选与可信程度、连续稳定时长、最终事件、游戏状态；找到第一项异常，给出它排除了哪些层、属于哪一层、最小修复是什么。用模拟帧测试和实际页面复测，报告修复前后证据。
4 · 替换一个工具
评估把当前手部识别提供者换成本地替代方案。先读取 gesture-engine 输入契约，候选方案必须输出标准化关键点、动作候选、可信程度、左右手和时间戳，并满足浏览器实时、可离线、许可可用。只修改输入适配器；除非多个可信方案都证明契约错误，不得改写稳定规则、事件或游戏状态机。运行同一组测试并比较延迟、误判和恢复方式。
5 · 迁移到第二件作品
保留 gesture-engine、输入适配器、诊断轨迹和测试，新建“手势节奏挑战”作为第二件作品。不要复制守城玩法换皮：重新设计节拍状态与计分，只复用统一动作事件。列出原样复用与重新创建的模块，并证明相同模拟输入在两个作品中产生一致事件。

看行为与证据，不看代码数量

完成标准与真正学会的标准

  • 移动、握拳、张手三种输入可完成 3 局；单帧错误不触发施法，手消失会安全取消。
  • 目标电脑连续运行三局无累积卡顿；课堂目标是游戏通常保持 50 帧/秒以上，但以实测为准。
  • 摄像头拒绝、模型加载失败或识别不可用时显示清楚原因和键盘回退，不出现空白页。
  • 诊断栏能定位视觉、稳定、状态或渲染中的第一处异常。
  • 素材、关卡节奏和核心行为由你定义，不把官方示例或他人完整游戏当成成品。

五项原理掌握检查

  1. 不说工具名，解释像素如何成为稳定施法。
  2. 预测稳定时长从 400 改为 700 毫秒的效果与代价。
  3. 根据中间数据指出问题落在哪一层。
  4. 写出替代识别器必须满足的输入输出契约。
  5. 新增一个动作，并把 gesture-engine 迁移到节奏游戏。
已确认Google 官方 Web 文档提供手势、左右手和关键点输出，并明确视频识别会阻塞界面线程；Phaser 当前包为 4.2.1，官方建议新项目使用 Phaser 4；Node.js 24 为长期支持版本。
合理推断把识别放入 Worker、只把最新结果送给游戏，通常能减少界面卡顿；实际收益取决于目标电脑，必须运行测量。
尚未确认教室电脑的摄像头、光线、CPU 和实际识别延迟；400/600/1200 毫秒均为起始参数，不是已经验证的最佳值。
总体判断A 级路线：关键链路有官方文档与示例；新手难度中等。停止继续选型的理由是三个组件已覆盖必需能力，更多工具只会增加连接成本。
