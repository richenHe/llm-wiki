## Design Specificity Verdict

页面视觉很有辨识度，像一份“科学考察地图＋教师研究档案”，不是随便套出来的卡片网站。树干、分叉、纸张式节点、证据边界都契合主题。然而教学路径的针对性不足：机器学习、强化学习、AlphaFold、Figure工厂案例和脑机接口难度完全不同，却全部采用同样的18板块和近似视觉重量。因此它成功表达了“资料很多且严谨”，没有成功表达“一个零基础教师下一步只需学什么”。

自动检测器对 `index.html` 返回0条规则问题，浏览器检查也确认55个节点、51张抽查图片、2个视频和页内链接都能工作。这说明主要问题不是文件损坏或按钮失效，而是信息架构和教学顺序。自动检测另外没有覆盖教学理解，也不能把0条结果解释成页面容易学懂。

## Cognitive Load

- [x] 单一焦点失败：首页先展示两种视图、六个筛选和55个节点，没有唯一开始按钮。
- [x] 分块失败：页面虽然分成18节，但每节都被算作同一条必读进度，没有核心与扩展分界。
- [ ] 视觉分组基本通过：板块边界、标题和关系分组清楚。
- [x] 视觉层级失败：公式、论文、课堂讲法、核心例子都处在同一条100%进度中。
- [x] 一次只做一件事失败：用户需要同时阅读、查术语、判断是否必学、记住前置和决定下一页。
- [x] 最少选择失败：总览渲染后有122个可见交互控件。
- [x] 工作记忆失败：基础模型页需要同时保留 Transformer、自监督、规模化、预训练和适配的关系。
- [x] 渐进揭示失败：折叠了少量细节，但没有先给“学到这里就够了”的可完成核心层。

共7项失败，属于高认知负担。问题不是知识本身必然很难，而是页面把导航负担、专业内容负担和备课选择负担同时交给了用户。

## Emotional Journey

首页的大标题和知识树让人先产生好奇；看到55个节点后变成选择焦虑。详情页前7段中的问题、反差、类比和完整例子往往能暂时建立信心；进入第8—16段后，相同主线被迁移例子、失败、术语、理论、流程、系统、视觉和证据不断重述，用户开始疲劳并怀疑自己。第18段终于出现30秒、2分钟和5分钟讲法，教师才看到实际用途，但它出现得太晚。返回首页后又没有已学状态和下一步，方向感再次丢失。

## Strengths

1. 证据边界严谨。例如 Figure 页面明确区分“参与某个生产工序”和“机器人独自制造整车”，避免用震撼视频夸大事实。
2. 部分例子能够真正解释原理。例如强化学习用眼前 `+3`、后来 `-10` 与另一条路径的长期回报形成可计算反转。
3. 教师提取卡方向正确。30秒、2分钟、5分钟讲法正是教师需要的东西，只是入口顺序放反了。

## Priority Issues

### P0：没有零基础教师的唯一学习路线

首页要求用户先理解整个知识体系，才能开始学习。页面说“沿唯一主干”，实际根部有多个入口，基础模型之后又出现多个并行方向。例如教师进入首页后看见55个节点，却没有“第一次学习：只走这6站”的入口。

直接影响是用户无法判断先学什么、哪些可以跳过，也会把55个资料节点误认为55项学习任务。这是造成“顺序乱”的首要原因。

### P1：18板块把资料完整性错误地当成学习递进

前7段大体合理：位置、前置、问题、反差、本质、类比、完整例子。第8—16段则反复扩张同一主线。六个抽查页面平均约8390个可见字符，Figure页面约10340个字符、24个术语、13张图片和1个视频。

直接影响是用户无法获得“已经学会”的结束感。即使看懂了完整例子，页面仍告诉他后面还有11段同等重要的内容。

### P1：专业词出现在理解它的情景之前

AlphaFold很快出现 Pairformer、MSA、pLDDT、PAE；Figure首屏出现顺序物流、移动操作一体、VLA和全身控制；脑机接口在人物情景建立前出现流式解码、语言先验、声学特征和在线闭环。

例如应该先写“系统一边收到新的脑信号，一边继续生成声音”，再补充“这叫流式解码”。当前顺序常常先给名称，再等用户主动点击解释。

### P1：主干与应用分支的先后关系表达冲突

机器人、科学、生成世界和脑机接口本应是基础模型后的并行选修，却被命名成“大枝一、大枝二、大枝三、树冠”，真实脉络又排列成连续章节。用户很容易误以为必须先学机器人，才能学制药和脑机接口。

### P1：教学目标、例子和细节没有按知识难度分别设计

机器学习的100封邮件例子适合零基础者；强化学习一开始却要求手算折扣回报；AlphaFold只用一句“结构不是序列”就跨入蛋白质专业概念；Figure首屏同时放入技术架构、工厂数字和证据等级。统一模板没有补足各领域不同的基础缺口。

### P2：教师最需要的课堂讲法在页面末尾

第18段才出现30秒、2分钟、5分钟版本。教师需要先看“最终我要讲成什么样”，再决定哪些原理和证据值得深入，而不是读完17段后才知道学习目标。

### P2：次要界面与无障碍问题增加阅读阻力

详情页青绿色小字对比度约3.91:1，目录序号约2.48:1；术语浮层被声明为简单提示却包含按钮和折叠内容；当前目录项没有标准的读屏状态；部分触控目标小于44×44像素。这些不是“完全看不懂”的主因，但会让低视力、键盘和注意力困难用户更累。

## Persona Red Flags

### 零基础用户

会把“资料库完整度”误认为“学习要求”。看到 Figure 页首的企业数字、VLA、全身控制和证据等级，会认为这些内容必须一次掌握，从而快速退出。

### 需要辅助支持的用户

18项侧栏、超长页面、小字号与低对比文字、不可正确朗读状态的浮层会增加导航和注意力负担。例如放大查看图片后，键盘焦点不会稳定回到原图片按钮。

### 备课教师

“先学懂”和“查资料”没有分开。快速备课者可能直接跳到课堂讲法却不理解证据；认真从头读的人则要经过17个板块才看到可上课版本。跨多个节点时也没有“已掌握、加入本节课、稍后复习”等状态。

## Minor Observations

- 首页1440×900首屏看不到任何知识节点，主要空间被标题和课程判断占用；第一步入口需要继续滚动才出现。
- 窄屏页面虽无横向溢出，但 Figure详情可长达约38085像素。
- 每个详情页都会加载约1.1MB脚本，其中大部分是其他节点数据；本地使用影响有限，但结构上说明资料与单页学习没有分离。
- 页面中的返回、图片文字说明、键盘焦点、减少动画设置和媒体延迟加载做得较好。

## Questions to Consider

1. 如果用户第一次只允许学习6个节点，哪6个节点足以解释“基础模型为什么带来机器人、制药、游戏和脑机接口”？
2. 每个节点读到哪一段，就可以明确告诉教师“核心已经学会，后面只是备课扩展”？
3. 专业词是否都能遵守“先给普通情景，再给中文解释，最后才给专业名称”？
4. 应用分支能否明确标成“任选案例”，而不是继续用容易被理解成先后顺序的章节编号？
