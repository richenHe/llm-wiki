# Product thesis

The learning surface turns a large knowledge base into a hollow, navigable sphere. The sphere is not a decorative globe: its silhouette is formed only by knowledge points and relationship lines, so the learner can see structure without losing space to a solid object. For example, a 300-node topic shows a stable visible slice instead of placing 300 labels on screen at once.

# Visual language

The existing LLM Wiki shell remains quiet and white. The learning surface adds graphite hairlines, cobalt for the current learning focus, and restrained violet for cross-topic relationships. There are no continents, glass bubbles, gradients used as decoration, or floating dashboard cards. For example, a cross-topic link appears as one violet ring point near the sphere, not as another miniature sphere.

# Composition

The sphere is the protagonist. A compact knowledge-path panel sits at the upper left; search and primary learning actions sit in the header; learning order appears only when it is useful in the lower right. Details are an on-demand drawer, not a permanent wall. For example, hovering “营” can show `客 → 品 → 场 → 服 → 营 → 财 → 增` without shrinking the sphere into a small illustration.

# Interaction and motion

Clicking a node smoothly moves into its context. Direct children become the foreground, siblings remain visible as context, and unrelated nodes recede. Cross-topic points move to the target context with the same camera transition. Motion is brief, interruptible, and removed when the operating system requests reduced motion. For example, clicking “加速度” keeps “速度” nearby and reveals its own children instead of abruptly loading a new page.

# Scale and accessibility

The canvas uses semantic zoom and a visible-node window; the path panel remains a complete keyboard-accessible alternative. Text contrast follows the existing product tokens, controls have visible focus states, and the canvas never becomes the only way to reach knowledge. For example, if a topic has 80 children, the sphere shows 24 at a time while the directory panel can scroll through all 80.

# Responsive behavior

Desktop keeps the path panel and sphere together. Narrow windows reduce the path panel and route width while preserving a scrollable path and all primary actions. The MVP targets the Windows desktop window and does not yet turn the path panel into a mobile bottom sheet. For example, at a narrower desktop width the directory remains 220 pixels wide and scrolls independently.
